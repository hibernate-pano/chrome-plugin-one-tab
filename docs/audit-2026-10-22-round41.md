### 本轮的一个前提修正（很重要）

`manifest.json` 的 `action` **没有 `default_popup`** ⇒ 用户点图标走
`chrome.tabs.create()` 打开一个**普通标签页**。所以：

> **管理页的宽度由用户的浏览器窗口决定（1024 / 1280 / 1440 / 1920 都常见），
> 不是 400px。**

前一轮（round2）已经纠正过一次「400px popup」的测量前提。本轮沿用真实宽度重测，
并新增了 **1024px** 这一档（半屏分屏 / 13 寸笔记本的常见宽度）。

# 一、主审亲自确认的问题（全部有真机证据）

## 0. 主审的结论先行

这个产品**工程质量远超同类独立扩展**（166 个测试文件、mutation 验证、
fail-closed 纪律、诚实的文案）。但从「拿得出手」的标准看，它现在更像一个
**功能完整但没被打磨过的内部工具**，而不是一个**商业产品**。差距集中在三处：

1. **信息层级是反的**：管理页的头号任务是「找回」，而页面上最响的那颗按钮
   是「保存并关闭」—— 一个会把用户当前窗口清空的动作。
2. **列表管理能力只有「加」没有「理」**：排序写死、不能固定、不能批量。
   攒到 30 个会话以后，用户只能靠搜索框找。
3. **打磨的缺口在「看起来像原型」的地方**：搜索无结果的卡片内容溢出框外、
   主题预览是硬编码色块、暗色模式下不跟随。

## 1. 视觉与布局

### L-1 · P1 · 搜索无结果的空态**内容溢出卡片外**（真机截图坐实）

- **位置**：`src/components/search/SearchResultList.tsx:761` —— `<EmptyState … className="h-40" />`
- **证据**：`outputs/lead-interact/06-search-empty.png`。浅蓝卡片只包住
  **图标 + 标题**；**描述句和「小提示」三条 bullet 全部掉到卡片边框外面**，
  浮在页面底色上，看起来像「卡片裂开了」。
- **根因**：`EmptyState` 的内容（图标 64px + 标题 + 描述 + action 块）约需 300px，
  而调用方硬写了 `h-40`（160px）。组件没有 `overflow-hidden` ⇒ 内容**溢出**而不是被裁，
  于是渲染成「一半在框里、一半在框外」。
- **顺带**：`action` 里塞的「小提示」三条 bullet 是**常驻帮助文案**，
  在「搜不到」这个时刻占掉整屏高度却不给任何可点动作。
- **最小修法**：① 去掉 `h-40`（或换成 `min-h-*`）；② 空结果的 action 改成
  一个真按钮「清空搜索」；③「小提示」降级成一行灰字或收进 tooltip。

### L-2 · P2 · 641–1024px：搜索框独占第二行且**居中**，与整体左对齐打架

- **位置**：`src/styles/global.css:1509-1533`（`min-width:641px and max-width:1024px` 档）
- **证据**：`outputs/lead-inspect/08-narrow-1024.png`。1024px 下搜索框在第二行，
  左右各留 ~250px 死区，而**卡片与品牌都在左对齐 x=16** ⇒ 搜索框是全页唯一
  居中的元素，视线要来回跳。
- **根因**：`.app-header-search` 的 `max-width: 32rem` + `margin-inline: auto`
  在**双行布局**下不再有意义（双行时搜索独占整行，应当**撑满并左对齐**）。
- **最小修法**：双行档里把 `max-width` 放开、`margin-inline` 改 `0`，
  让搜索框与下面的卡片左边缘对齐。

### L-3 · P2 · 主题风格预览是**硬编码浅色色块**，暗色模式下不跟随

- **位置**：`src/components/layout/ThemeStyleSelector.tsx:140-225`（`themeOptions[].previewColors`）、
  预览卡 `ThemePreviewCard`（:229-275）
- **事实**：6 套主题的 `previewColors` 全是**写死的浅色十六进制**
  （如 creamy `{bg:'#faf8f5', card:'#fffdf9', accent:'#d4a574'}`），
  **没有任何暗色变体**。而设置页文案写着「点下面任意一个预览立即切换，
  全局配色（含这个页面）立刻跟随」。
- **后果**：暗色模式下打开设置页，6 张预览卡仍是浅色的 —— 「立刻跟随」这句话
  在**预览卡本身**上不成立（页面的其余部分确实跟随了 ⇒ 用户会以为预览卡坏了）。
- **更本质的问题**：预览画的是「三根色条」，不是这个主题的样子。
  Apple 与 Chrome 两张几乎无法区分（都是蓝+白），用户选主题时**没有真实依据**。
- **最小修法**：预览改成**用真实主题 CSS 变量渲染的一张小会话卡 mock**
  （`.theme-*` 类名 + 一张假卡片），这样 ①它天然跟随明暗模式与主题；
  ②用户看到的是「这个主题下界面长什么样」，而不是抽象色条。

### L-4 · P2 · 设置页**没有品牌标识**，与管理页不一致

- **位置**：`src/options/OptionsPage.tsx` 页首
- **证据**：`outputs/lead-inspect/09-options.png`。管理页顶栏有橙色的 TapStack
  标志 + 品牌名；设置页首行是纯文字「TapStack 设置」。
- **为什么是问题**：设置页是**独立标签页**，很多用户是从扩展详情页进来的
  —— 他看到的第一个东西不像这个产品的一部分。
- **最小修法**：复用 `TapStackLogo`（`src/components/common/TapStackIcon.tsx`）。

## 2. 信息层级与控件

### L-5 · P1 · 顶栏「保存并关闭」在**有会话时**是页面上最响的按钮 —— 层级倒置

- **位置**：`src/components/layout/Header.tsx:487`
  `className={`btn ${groups.length === 0 ? 'btn-secondary' : 'btn-primary'} …`}`
- **事实**：**空态时**它被刻意降为次级（那是 2026-10-19 审计 I-1 的成果，
  注释就在 :476-482）。但**有会话之后**它恢复成 `btn-primary`（实心蓝），
  而这时页面上**空态卡不存在**、用户正在做的是「找回」。
- **证据**：`outputs/lead-inspect/01-desk-full.png`。1440px 下顶栏最右那颗
  实心蓝按钮是「+ 保存并关闭」；同一行里还有绿色「上传」、蓝色「下载」
  三个同色系实心按钮并排 —— **四颗实心按钮抢注意力**，
  而列表里每张卡的「恢复」动作只有 16px 的灰色小图标。
- **为什么是问题**：
  - 「保存并关闭」是**本页唯一一个会清空用户当前窗口**的动作；
  - 它是**低频**动作（存一次就完了），而「找回」是**高频**动作；
  - 页面的主任务在下面的列表里，不在顶栏。
- **最小改法**：
  - 把它从 `btn-primary` 降为 `btn-secondary`（**任何时候**都降），
    让空态卡的主 CTA 成为全页唯一的实心主按钮；
  - 「上传 / 下载」两颗同步按钮从实心色块降为 `btn-icon`（与主题/菜单同级），
    靠 tooltip 与 hover 说明，不要各占一个色块；
  - 这样顶栏只剩**一枚**实心按钮或**零枚**实心按钮。

### L-6 · P2 · 菜单里「去登录」与「登录 / 注册」两个入口做同一件事

- **位置**：`src/components/layout/HeaderDropdown.tsx:767-783`（状态行里的「去登录」）
  与 `:808-818`（菜单项「登录 / 注册」）
- **事实**：未登录 + 云端后端时，**两个入口同时出现**，都调 `onOpenAuth('login')`。
  实机截图 `outputs/lead-inspect/04-menu.png` 里能同时看到
  状态行右上角的蓝色下划线「去登录」和下面的「登录 / 注册」菜单项。
- **为什么是问题**：一个菜单里两个同义入口 = 用户会以为它们不一样；
  也让菜单看起来像没设计完。
- **最小改法**：`needsLogin` 为真时**不渲染**独立的「登录 / 注册」菜单项
  （状态行里的「去登录」已经够），反之亦然。

### L-7 · P2 · 会话卡 5 颗纯图标按钮，其中两颗「打开」图标**几乎同形**

- **位置**：`src/components/tabs/TabGroup.tsx:896-909` 的注释自己写着：
  「两个『打开』图标在 16px 下几乎同形（用户分不清『新窗口恢复』与『当前窗口打开』）」。
- **事实**：该问题**只在窄屏（<640px）**被处理（收进「更多」菜单）；
  **≥640px 时两颗近似图标仍然并排平铺**。
  真机截图 `outputs/lead-inspect/02-card-header.png` 上，
  第 1 颗（↗ 出框）与第 2 颗（→ 出框）第一眼确实读不出差别。
- **为什么是问题**：卡片头是「找回」动作发生的地方，
  而这里的第一颗和第二颗恰好是**两个不同的打开语义**。
- **最小改法**：
  - 「在当前窗口打开」是**低频且危险**的（它会把当前窗口塞满），
    收进「更多」菜单，与重命名/锁定/删除并列；
  - 卡头平铺只留「折叠 / 恢复（新窗口）/ 更多」三颗。

### L-8 · P2 · 会话标题是 `<h3 tabIndex={0}>`，承担「点击重命名」但没有可交互语义

- **位置**：`src/components/tabs/TabGroup.tsx:851-865`
- **事实**：`<h3 … tabIndex={0} onClick={() => !group.isLocked && setIsEditing(true)}>`
  —— 一个**标题元素**同时是「可 Tab 到的可交互元素」。
  没有 `role="button"`、没有「按 Enter 可重命名」的可访问名
  （`title` 属性只在鼠标悬停时出现，读屏用户拿不到）。
- **附带问题**：锁定会话的标题仍带 `cursor-pointer` 与 hover 样式，
  但 `onClick` 里 `!group.isLocked` ⇒ **点了没反应**（只有 `title` 提示说明了原因）。
- **最小改法**：给 `h3` 加 `role="button"` 与条件化的 `aria-label`
  （「重命名会话：{名}」/「会话已锁定，先解锁才能重命名」），
  锁定时去掉 pointer 光标与 hover 态。

### L-9 · P2 · 锁定 / 解锁会话**零反馈**

- **证据**：`outputs/lead-interact/report.json` 的「锁定会话」一步
  `visible: []` —— 页面上没有任何 toast / inline 提示。
  唯一的反馈是卡片头多了一颗锁图标 + 按钮 aria-label 变成「解锁会话」。
- **为什么是问题**：锁定是**有语义的状态变更**（它会改变「恢复后是否消费」的行为），
  而这个语义**只写在 tooltip 里**。用户锁完不知道自己改变了什么。
- **最小修法**：锁定成功给一条 toast，说清后果
  （「已锁定。该会话恢复后不会被移除，可反复使用。」），解锁同理。

## 3. 产品能力缺口

### L-10 · P1 · 列表排序**写死**「保存时间倒序」，没有任何排序入口

- **位置**：`src/components/tabs/TabList.tsx:243-245`
  ```ts
  const sortedGroups = [...groups].sort((left, right) =>
    new Date(right.createdAt).getTime() - new Date(left.createdAt).getTime());
  ```
  且紧接着 `const filteredGroups = sortedGroups;`（变量名是残留 —— 筛选曾经在这里做）。
- **事实**：全仓没有任何 `sortBy` / 排序控件。
  筛选面板提供「域名 / 会话名称 / 保存时间」三个**筛选**维度，但**没有排序**维度。
- **为什么是问题**：这是「攒起来稍后找回」的产品 —— 攒到 30 个会话后，
  用户唯一的办法是搜索框。而「按名称排」和「按最近更新排」是找回场景里
  最常用的两个序。筛选能收窄集合，却不能改变**顺序**。
- **最小修法**：在筛选面板同排加一个排序下拉（最近保存 / 最近更新 / 名称），
  判据抽成纯函数（`src/core/sessionSort.ts`）以便单测。
  默认仍为「最近保存」，**不改现有默认行为**。

### L-11 · P1 · 空状态只给「保存并关闭」一条路 —— 换设备用户与 OneTab 老用户是死路

- **位置**：`src/components/tabs/TabList.tsx:272-310`
- **证据**：`outputs/lead-inspect/07-empty.png`。空态卡只有一颗
  「保存并关闭」主 CTA，**没有**「导入数据」「登录后从云端恢复」的任何入口。
- **为什么是问题**：走到这个空态的用户有三种，界面只服务了其中一种：
  | 用户 | 他真正需要的下一步 | 界面给的吗 |
  |---|---|---|
  | 全新用户 | 保存一个工作会话 | ✅ 给对了 |
  | 换设备的老用户（已登录/已配云盘） | 「从云端把我的会话拉回来」 | ❌ 没有 |
  | OneTab 老用户 | 「把 OneTab 导进来」 | ❌ 没有 |
- **最小修法**：空态的次级动作区加两个**次级按钮**：
  「从云端恢复」（已登录/已配置后端时出现，点了走一次手动下载）
  与「导入数据」（走已有的 JSON / OneTab 导入入口）。
  ⚠️ 这两条都**不是**新功能，导入与手动下载**已经存在**，只是空态没给出口。

### L-12 · P2 · 会话卡没有任何视觉身份 —— 一屏 10 张卡长得一模一样

- **证据**：`outputs/lead-inspect/01-desk-full.png`。每张卡的标题左侧只有
  一个折叠箭头，没有 favicon、没有域名色块。
- **为什么是问题**：会话名默认取「出现最多的域名」（如 `github.com`），
  也就是说**同一站点的会话会连着出现好几个**，而它们在视觉上完全无法区分。
  标签行有 favicon，卡片级没有 —— 层级倒挂（行比卡更可辨识）。
- **最小改法**：卡片标题左侧加**会话域名 favicon**（首标签的 favicon，
  或按域名取的字母/色块），复用已有的 `SafeFavicon` 与「显示网站图标」开关。
