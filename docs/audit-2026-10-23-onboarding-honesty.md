## 2. 结论先行

1. **一条真问题（不是骗人，是「点不准」）**：引导让用户去菜单里找「去登录」。那个入口**在、可见、可点**（截图实测），但它的**命中区只有 36.4×16px**，是其它菜单项（254×36）的 1/7，字号 12px vs 13px，且是菜单里**唯一没有图标**的一行。手机上点不准、键盘用户看不出它是菜单项。**注意：它「贴着状态行」是有意的设计（`syncStatusHonesty.test.ts:335` 把这个理由写进了守卫），本条要修的是命中区与视觉规格，不是把它挪走。**
2. **一条假精确**：引导说「固定标签页可保留，也可一并保存」，暗示这是**随时可用的开关**。真实情况是它**默认关**，且**要��设置页**才能开 —— 引导从头到尾没提「设置」两个字。
3. **一条被上一轮改了一半的**：「自动同步」卡片标题 + 「保存后会自动同步到云端」里的「自动」，在中文里默认含「持续、双向」，而**定时拉取默认是关的**。上一轮补了「定时拉取默认关闭」在第 3 行，但**标题**和**第 2 行**没改。
4. **引导漏教了三个高频东西**：**锁定**（唯一能让恢复后不被消费的开关）、**会话排序**（42 轮新功能）、**在当前窗口恢复**（真实存在的第二个入口）。
5. **一个术语问题**：引导卡片标题混用英文 `Pinned` / `pinned`，产品其它地方一律叫「固定标签页」。

## 3. P0

### H-1【P0】引导让用户去菜单里点「去登录」，但那个入口的**命中区只有 36.4×16px**（其它菜单项 254×36）

- **原话**（`src/components/onboarding/OnboardingSteps.tsx:176`）：
  > `通过右上角菜单「{MENU_LOGIN_LABEL}」开启同步`
  >
  > 常量（`src/components/common/menuLabels.ts:22`）：`export const MENU_LOGIN_LABEL = '去登录';`

- **它承诺了什么**：菜单里有一项叫「去登录」，这是开启同步的入口。

- **实际是什么（**跑出来的**，不是读代码猜的）**：

  入口**在**，也**可见**（截图 `outputs/v43-honesty/01-menu-with-denglu.png`：菜单顶部状态卡里，右上角是蓝色下划线的「去登录」）。**上一轮 P0-2 的修法是对的**。

  但它的**规格与菜单里其它每一项都不同**（实测数据见 §0）：

  | | 「去登录」 | 其它 7 个菜单项 |
  |---|---|---|
  | 命中区 | **36.4 × 16 px** | **254 × 36 px** |
  | 字号 | **12px** | 13px |
  | 图标 | **无**（唯一一行没有图标） | 每行一个 16px 描边 SVG |
  | 位置 | **状态卡内**，与「未登录」抬头同一行右侧，**不在菜单项垂直序列里** | 垂直序列 |
  | 样式 | 蓝色 + 下划线（像超链接） | `text-gray-700` 普通菜单行 |

  ⇒ **它在视觉上像一句说明文字，不像一个菜单项**；在触屏上 16px 高的命中区**几乎点不准**。

- **⚠️ 但「放在状态卡里」是**有意的设计决定**，不是疏忽**（本条必须说清，否则会误导修复）：
  - `src/components/layout/HeaderDropdown.tsx:894-910` 的注释写明：删掉独立菜单行、**只留状态卡内联那个**，理由是「它紧挨着『TapStack 云端 · 未登录』这一行状态，因果关系一目了然」。
  - `tests/syncStatusHonesty.test.ts:335-340` 把这个决定**写成了守卫的理由**：「现在只留内联那个：它紧挨着……因果关系一目了然；且与 WebDAV 的『去设置』内联入口是同一套语言。」

  ⇒ **本条要修的是「命中区」与「视觉规格」，不是「位置」。** 把它挪出状态卡会**推翻上面那条有意的设计**（因果邻接性），并且会让 WebDAV 的「去设置」内联入口变成唯一的例外 ⇒ **不建议挪**。

- **用户照做的具体后果**：
  - **触屏/窄屏**：用户找到那行蓝色小字，**点不中**（16px 高的文字，下沿还紧挨着状态卡的下一行「定时拉取：未开启」）⇒ 反复点不动 ⇒ 以为菜单坏了。
  - **键盘用户**：`role="menuitem"` 补上了（2026-10-20 的可达性修复），方向键能走到它 —— 但**走到时没有任何视觉反馈说「你到了一个菜单项」**（它长得像一行说明）。
  - **读屏用户**：读到「去登录，菜单项」⇒ 完全正常。**这一类用户没问题。**

- **诚实度定性**：不是「骗人」（它确实叫「去登录」、确实是入口、确实可见），是「**指了路，但路标本身比别的路标小 7 倍**」。上一轮 P0-2 修掉的是「字面量对不上」，本条是**同一处入口的另一半**。

- **建议改法（**首选：保位置、只治规格**，1 行 className）**：
  把 `HeaderDropdown.tsx:847-863` 的 className 从
  ```
  shrink-0 text-xs font-medium text-primary-600 underline hover:text-primary-700 dark:text-primary-400 dark:hover:text-primary-300
  ```
  改成
  ```
  shrink-0 text-sm font-medium px-2 py-1.5 -mr-2 rounded theme-btn-hover text-primary-600 underline hover:text-primary-700 dark:text-primary-400 dark:hover:text-primary-300
  ```
  ⇒ 命中区从 **36.4×16** 变成约 **52×28**（仍保留与状态行紧邻的因果关系与下划线线索），字号与其它菜单项一致。

  **若还要更多**（可选，属新增功能不是文案修复）：给它加一个 16px 描边 SVG 图标（与菜单其它行同规格）—— 状态卡抬头那一行会变成「图标 + 去登录」，与「未登录 · TapStack 云端」并列。

  **不建议**：把它挪成独立菜单行（会推翻 `HeaderDropdown.tsx:894-910` 与 `tests/syncStatusHonesty.test.ts:335-340` 记录的有意设计）。

- **配套**：`menuLabels.ts` 的文件头补一句 ——「这个常量管的是**字面量**；入口的**命中区/视觉规格**由 `HeaderDropdown` 保证。两件事。」

- **⚠️ 改前必读的两个守卫**：
  - `tests/guards/uiTruthfulnessC.test.ts:313` — 断言源码里渲染了 `{MENU_LOGIN_LABEL}`（**改 className 不影响它**；把文字删掉会让它红）。

### H-2【P1】引导第 2 步说「固定标签页可保留，也可一并保存」，把一个**默认关闭、藏在设置页**的开关说成随时可用的能力

- **原话**（`src/components/onboarding/OnboardingSteps.tsx:85-86`）：
  > ```
  > <div className="onboarding-feature-title">Pinned 可选</div>
  > <div className="onboarding-feature-desc">固定标签页可保留，也可一并保存</div>
  > ```

- **它承诺了什么**：这是一个**用户可自己决定**的选项 —— 「可保留，也可一并保存」，两个方向都摆在明面上。

- **实际是什么**：
  - `src/utils/storage.ts:316` — `collectPinnedTabs: false,`（**默认关闭**）。
  - `src/background/TabManager.ts:131` — `const collectPinnedTabs = settings.collectPinnedTabs ?? false;` ⇒ 默认**不保存**固定标签页。
  - `src/background/TabManager.ts:142-146` — 被丢弃的固定标签**既不保存、也不关闭**，就留在原处。
  - 唯一的开关在**设置页**：`src/options/OptionsPage.tsx:972-976`（`label="保存时收集固定标签页"`）—— **引导里没有任何一处提到「设置」两个字**。

- **用户照做的具体后果**：新用户 pin 了 3 个工作台标签 → 点「保存并关闭」→ 提示「已保存 12；另有 3 个固定标签页未保存（仍留在浏览器里，可在设置中开启『保存固定标签页』）」（`saveFeedbackCopy.ts:51-54`，**这一层兜住了**）⇒ **但引导本身从没告诉他「你还可以反过来做」**。他看到的引导是一句「可保留，也可一并保存」，读到的预期是「界面上有这个东西，我没找到而已」——**而他确实找不到**，因为它不在引导里、不在管理页里，只在设置页里。

- **诚实度定性**：不是谎报（「可保留」= 事实成立），是「**假可选**」——把一个**默认关、藏在另一个页面**的开关说成「随你」。

  > ```

  > <div className="onboarding-feature-desc">默认不保存浏览器里钉住的标签页，它们会留在原处；想一并存进会话，可在设置里打开「保存时收集固定标签页」</div>
  > ```

  标题顺带把英文 `Pinned` 改成中文（理由见 **H-11**）。

### H-3【P1】引导第 5 步的**卡片标题「自动同步」**与「保存后会自动同步到云端」，仍在用「自动」形容**默认关闭**的定时拉取

- **原话**（`src/components/onboarding/OnboardingSteps.tsx:188` / `:198` / `:203`）：
  > ```
  > 188:  保存后会自动同步到云端；新设备登录后会自动拉回云端的会话
  > 198:  定时拉取默认关闭，可在设置里打开
  > 203:  <div className="onboarding-feature-title">自动同步</div>
  > 207:  <div className="onboarding-feature-desc">保存和重命名都会上传到云端；定时拉取可在设置里开启</div>
  > ```

- **它承诺了什么**：「自动同步」= 持续、双向、无需再管。

- **实际是什么**：
  - **上传**确实自动（`TabManager.ts:203` 调 `syncEngine.scheduleUpload`；`scheduleUpload` **不检查** `syncEnabled`）⇒ 这半句为真。
  - **拉取**默认**关**（`src/utils/storage.ts:302` — `syncEnabled: false`；后台 alarm 只在 `syncEnabled === true` 时注册）⇒ 「登录后会自动拉回」= **登录那一刻拉一次**（`restoreAfterLogin.ts`），**之后不会自动拉**。

- **为什么第 42 轮的修法只修了一半**：P1-5 的修法是**在第 188 行后面补了第 198 行**「定时拉取默认关闭，可在设置里打开」。**信息完整**上是对的，**阅读顺序**上失败：
  1. **卡片标题「自动同步」**（`:203`）承诺了一个**默认关着**的功能 —— 用户读完标题形成的预期（「有自动同步这回事，默认开着」）要读到描述的后半句才被推翻。**标题是最先被眼睛捕获的。**
  2. 第 188 行「保存后**会自动**同步到云端」在**这个 `<p>` 的第二行**，比第 198 行先被读到。而「自动同步到云端」在中文里通常被读成**单向**（A→B），所以**上传**那半句没问题；**问题出在「会自动拉回」** —— 「登录后」这个状语把它限定在了登录那一刻，**字面为真**，但**读起来像「之后也会持续拉」**。

- **用户照做的具体后果**：用户读完第 5 步（标题「自动同步」很显眼），认为**同步默认是通的**。两台设备都在线时，A 存的会话**不会**出现在 B ⇒ 他得出「这产品同步不可靠」。

- **建议改法**（两处）：

  1. `OnboardingSteps.tsx:203-207` —— **标题**去掉「自动」，描述把默认状态前置：
     > ```
     > <div className="onboarding-feature-title">云端同步</div>
     > <div className="onboarding-feature-desc">保存和重命名都会自动上传到云端；定时拉取默认关闭，可在设置里打开</div>
     > ```
  2. `OnboardingSteps.tsx:188` —— 让限定词**紧跟动词**：
     > ```
     > 保存后会自动上传到云端；新设备登录时会拉回云端的会话

  ⇒ 导出成 OneTab 再导回来，**每个会话的名字都会变成「导入的会话 1、2、3…」**（`deriveImportedGroupName` 的序号兜底）。而 `src/domain/tabGroup/sessionName.ts:141-146` 解释了为什么**不能**用时间戳兜底（幂等指纹会失效）⇒ **这个损失是设计上的、不可改的**。

- **用户照做的具体后果**：用户导出成 OneTab（为了拿去 OneTab 里开）⇒ 导回来 ⇒ **一屏「导入的会话 1、2、3…」** ⇒ 他会以为 TapStack 坏了。

- **建议改法**（`OnboardingSteps.tsx:212`）：
  > ```
  > <div className="onboarding-feature-desc">支持 OneTab 文本格式与 JSON 备份（OneTab 格式本身不带会话名，导回来会按域名或标题重新命名）</div>
  > ```
  **注**：`sessionName.ts:256-279` 的取值链是「主导域名 → 首个有意义的标签标题 → 时间戳」，U-06 修完后内网地址也产出主机名 ⇒ 「按域名或标题」对绝大多数场景为真。

## 12. 需要拍板的一条

**引导的定位**：`src/core/onboardingTrigger.ts:13-15` 写着
> `「引导是介绍新功能的」，不是安装向导`

但 `onboardingStorage.ts:186` 的写侧闸门让**更新触发的引导永远不出现**（§10 末段）。

**两个方向，选一个**（我给推荐）：

1. **【推荐】引导 = 一次性入门说明**（推荐理由：诚实、简单、零打扰，且与产品「安静」的定位一致）
   - 改**注释**：`onboardingTrigger.ts:13-15` 改成「引导是一次性入门说明；版本更新不再打扰」。
   - `isFeatureBearingUpdate` / `previousVersion` 合并逻辑**整体退役** ⇒ 代码变简单。
   - 菜单里的「使用引导」是唯一的再入口，**已经存在**，够用。
2. **引导 = 每版新功能介绍**
   - `hasCompletedOnboarding` 改为**按版本**记（比对 `previousVersion`）。
   - 但会**打扰**所有用户 ⇒ 与产品定位冲突 ⇒ 需要明确拍板。

**这一条不影响本轮其余 13 条结论的处置。**
