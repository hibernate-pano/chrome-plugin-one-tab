> **父蓝图**：`2026-08-05-tabstack-personal-revamp-blueprint.md`

## 0. 目的

在数据可靠 + 体验顺滑的基础上，加几个**只对你个人有用**的小功能。**重点是从候选池里挑出 1–2 个**——别全做。

---

## 1. 候选功能池（按价值 × 复杂度排）

| # | 候选 | 价值 | 复杂度 | 推荐 |
|---|---|---|---|---|
| **3.1** | **Hover-to-preview**：鼠标悬停会话卡 → 浮窗显示前 5 个 tab 的 favicon + 标题 | 高 | 中 | ⭐ |
| **3.2** | **"上次读到这"小条**：根据 tab URL 上次恢复时间，显示在该卡顶部 | 高 | 中 | ⭐ |

| **3.5** | **跨设备"待读"清单**：用 Supabase 同步 1 个轻量"待读"列表 | 高 | 高（跨设备） | 暂缓 |
| **3.6** | **暗色模式"自动"真正可用**：ThemeContext 修未达成的 prefers-color-scheme | 中 | 低 | ⭐ |

---

## 2. 推荐选 1–2 个

我作为架构师推荐 **3.1 + 3.6**：

- **3.1 Hover-to-preview**：你每天用 TabStack 找会话时，能"扫一眼再看详情"是高频动作；当前要点击一次才能看。
- **3.6 Auto 暗色模式**：已在诊断里标记为 "未达成"，原因清楚，修起来工作量小、立即有用。

**不推荐 3.5 跨设备待读清单**——复杂度高（数据模型跨设备 + tombstone + UI），个人项目 ROI 不够。

---

## 3. S3 详细 spec 何时写

S2 收尾 + S1 落地后。S3 spec 应在 S2 跑完**之前**起稿，以便 S2 实施时 UI 的视觉规范已经知道哪些位置会新增浮层 / 顶条。

预计：S2 跑 P5 阶段时同步起稿 S3 spec；S3 spec 提交时你已经过完 S2 视觉，可以确认"我要的就是 1 + 6"。

---

## 4. 验收

每个 S3 功能都要：
- 满足 S2 设计的视觉规范（主 CTA 唯一、hover 不用 scale、焦点环一致等）
- ≥ 80% 测试覆盖（含至少一个集成测试 / 烟雾测试）
- 不破坏 5 个不变量测试
- 不引入未批准的依赖（无 react-query / TanStack Router / 任何"又一颗大依赖"）

---

## 5. 不动

- 不为社群 / 商业化预设（纯个人项目）
- 不做付费墙 / 订阅模型
- 不做大规模插件系统 / marketplace
- 不做账号系统 / OAuth 多供应商
