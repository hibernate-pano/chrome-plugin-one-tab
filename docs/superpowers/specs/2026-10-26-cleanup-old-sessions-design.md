# 清理旧会话 —— 设计（2026-10-26）

> 状态：已与产品负责人逐条确认（2026-10-26）。执行前的最后一份口径来源。

## 1. 意图与来由

会话列表**只增不减**：未锁定的会话在被打开时会被消费掉，但**从来没被打开过的**会一直躺着；
OneTab 导入件一次就是几百条。现有两个出口只有两端——

- 单个会话删除（一次一个）；
- 「删除所有会话」（全有或全无）。

中间没有档。200 个会话的人要么一个个点，要么全清。**按保存时间清理是最自然的中间档**，
档位本身不需要发明（一个月 / 三个月 / 六个月 / 一年 / 全部）。

「删除所有会话」不再作为独立按钮存在，而是这组档位里的最后一档——
两个入口做同一件事只会让人更容易点错。

## 2. 非目标（明确不做）

- **撤销**：删除仍然是物理清除、无回收站（v1.22.0 起的既定行为，本功能不改变它）。
  误删的防线是确认框里的**名字预览**，不是事后撤回。
- **自动 / 定时清理**：静默删数据是另一件事，不在本轮。
- **标签级时间戳**：`Tab.createdAt` / `lastAccessed` 本来就有，但组内所有标签的时间
  都等于那次保存的同一瞬间 ⇒ 对「按年龄清理」零信息量。起作用的一直是**组级**时间。
- **回收站**：同上。

## 3. 判据核心：一条会话「有多旧」

```
参考时间 = 保存时间已知 ? createdAt : importedAt
```

- 「保存时间已知」的判据**只从** `@/core/sessionSaveTime` 的 `hasUnknownSaveTime` 出，
  不在这里内联判断（该模块文件头写明了为什么）。
- **为什么未知时间用 `importedAt`**：OneTab 文本格式不带时间戳，导入时 `createdAt` 被填成
  导入那一刻。但真实保存时间**只可能早于或等于**导入时间 ⇒
  「导入于三个月前」⇒「保存于三个月前」**必然成立**，用它做截断不会误伤。
- 反面（被否决的方案）：一律排除未知时间 ⇒ 去年导入的几百条旧收藏**永远清不掉**，
  四档对最大的一堆会话失效。

## 4. 界面

### 4.1 菜单

危险区那块整体换成一个子菜单「清理旧会话」，沿用现有导出/导入子菜单的展开方式
（流内展开、不绝对定位 —— `dropdownSubmenuReachable` 守卫的既有前提）：

```
清理旧会话  ▸
  一个月前的会话（3）
  三个月前的会话（12）
  六个月前的会话（18）
  一年前的会话（24）
  删除所有会话（保留 2 个锁定）
  删除所有会话（含 2 个锁定）
```

- **条数是磁盘真值**（`storage.getGroupsForWrite()`），与确认框同源；读失败时退回 Redux
  快照（菜单是**预告**，真正的承诺在确认框，那里读失败会中止）。
- **条数为 0 的时间档不显示**（没有可清理的就不摆出来）。
- **没有锁定会话时**，最后两行合并成一行「删除所有会话（N）」。
- 叫法沿用 **「删除所有会话」**（不引入「删除全部」这个第二叫法 ——
  `deleteAllActionNaming` 守卫就是在防这件事）。

### 4.2 确认框

走现有 `showConfirm`（`ModalFrame` 的描述区是 `whitespace-pre-line`，多段可换行）。
**不新做弹层组件。**

```
标题：清理 12 个会话
正文：
将删除 12 个会话，共 87 个标签页。
「GitHub 调研」8 月 3 日、「季度报告」7 月 21 日、「账单」6 月 2 日 等 9 个

另有 2 个已锁定的会话不会被清理。
其中 4 个保存时间未知（OneTab 导入），按导入时间计算 —— 它们至少有那么旧。

删除会同步到你的其他设备，对方离线期间的编辑也会一起消失。
删除后彻底清除：没有回收站，也没有撤销。
```

- 名字预览**最多列 6 个**，其余说「等 N 个」。日期用 `@/utils/sessionPresentation` 的
  既有格式化函数，不新写一个。
- 「另有 N 个已锁定的会话不会被清理」：仅时间档且 `lockedCount > 0` 时出现。
- 「其中 N 个保存时间未知」：仅 `unknownTimeCount > 0` 时出现。
- 最后两段（跨设备 / 不可撤销）直接复用现有同源文案
  （`crossDeviceDeleteCopy` 与 `deleteAllConfirmMessage` 的既有口径），不另写一份。
- **「全部」两档**的时间段没有「另有锁定的不会被清理」那句 —— 它们的语义就是「全部」。
  「含锁定」那档复用现有的 `deleteAllLockedWarning`（点名 N 个锁定也会被删）。

## 5. 执行路径

### 5.1 新增语义命令 `deleteGroups`

```
{ op: 'deleteGroups', groupIds: string[] }
```

- 载荷是**具体 id 列表**，不是「按规则自己算」。
  理由：确认框里列了那 12 个名字 ⇒ **名字就是承诺**。若让 SW 自己按时间规则重算，
  用户看到 12 个、实际可能删掉 13 个（这期间同步进来一条旧会话）。
- SW 侧：一次读盘 → 只删列表里**仍然存在**的 id → 一次落盘 →
  `noteDeletedGroups(ids)` 一次登记（它本来就吃数组，不用改）→ `scheduleUpload(DELETE_PRIORITY_MS)`。
- 回执：`{ count: 实际删除数 }`（口径与 `deleteAllGroups` 一致）。
- **不触发覆盖上传**：部分删除只走墓碑广播。`overwriteCloud` 是「本地即全部真值」的语义，
  用在这里会删掉云端那些「本机读不出来」的行 —— 那是仓库里记过的既有事故形态。

### 5.2 「全部」两档

- **含锁定**：完全复用今天的 `deleteAllGroups` op 与 `handleDeleteAllGroups` 流程
  （含 `deleteAllShouldPushOverwrite` 那一次覆盖上传）。一个字节都不改。
- **保留锁定**：收集所有未锁定 id，走新的 `deleteGroups`。

## 6. 成功回执（延续「安静的成功」口径）

- 实际删除数 == 确认框里的数 ⇒ **静默**（列表里那些会话不见了，界面自明）。
- 不等 ⇒ **说事实**：沿用 `deleteAllSuccessMessage` 的四种说法
  （删了 0 个 / 与确认一致 / 少于 / 多于），不为本功能另写一套。

## 7.5 设计稿评审后的四条裁决（2026-10-26，控制器）

Builder check 提出的四个未定点，逐条定死：

**R1 —— 三套确认文案，各管一段，不复用同一模板硬凑。**
- 时间档：标题「清理 N 个会话」，正文＝数量＋标签页＋名字预览＋（可选）未知时间说明。
- 「删除所有会话（保留 N 个锁定）」：标题「删除 N 个会话」，正文＝数量＋标签页＋名字预览
  ＋「另有 N 个已锁定的会话会保留」＋跨设备＋不可撤销。**不出**「保存时间未知」那句
  （这一档没有年龄筛选，那句话在这里没有意义）。
- 「删除所有会话（含 N 个锁定）」：**完全复用**现有 `deleteAllConfirmTitle` /
  `deleteAllConfirmMessage`，一个字不改。
理由：三档的语义本来就不同，硬套一个模板必然有两处说假话。

**R2 —— 菜单层：时间档不带小字，「全部」两档带。**
父行「清理旧会话」不带副标题（它就是展开）。四个时间档只显示条数——
256px 宽的菜单塞不下四段小字。两档「全部」保留第二行小字：
- 含锁定档 → 沿用现有 `deleteAllMenuWarning`（「其中包含 N 个已锁定的会话，也会被删除」）。
- 保留锁定档 → 新增 `deleteAllKeepLockedMenuWarning`：「将清空本地未锁定的全部会话，
  删除后无法恢复（N 个已锁定的会保留）…同步删除」。

**R3 —— 时间档条数＝「会被删的条数」，锁定与不满足年龄的一律不计。**
菜单说 3、确认框就必须说 3，不许出现「菜单 3 / 确认框 1」。因此：
- 时间档在**第四档全部会话都锁定时**算出来是 0 ⇒ 该行不显示（与「没有够旧的」同一条规则）；
- 「删除所有会话（保留 N 个锁定）」若未锁定数为 0 ⇒ 该行不显示；
- 任何一种档位算出 0 条，**不弹确认框**（复用 `planDeleteAll.nothingToDelete` 的既有形态），
  直接说明无事可做。`deleteGroups` 收到空数组一律返回 `count: 0`（不报错）。

**R4 —— 执行时必须跳过「此刻已锁定」的 id，且回执要说清。**
名单来自确认那一刻；另一台设备在这几秒内把某条锁上，按 id 硬删就违背了
「已锁定的不会被清理」这句承诺——**承诺要在执行时也成立，不能只在确认时成立**。
所以 SW 侧逐条判 `isLocked`，跳过并统计，回执 `{ count, skippedLocked }`。
回执口径：`skippedLocked > 0` 时说「已删除 N 个会话（M 个在你确认后被锁定，已跳过）」——
**不许**沿用「其余已被移除」，那对锁定情形是假话。
⚠️ 这条只管**时间档**与「保留锁定」档。「删除所有会话（含锁定）」走的是
`deleteAllGroups`，它的语义**就是**连锁定一起删（v1.22.0 的既定产品决定），
不受本裁决影响。

## 8. 留给实现者的决定

- 时间档截断的**日历月钳制**：3 月 31 日的「一个月前」= 2 月 28/29 日（不能溢出成 3 月 3 日，
  那会让截止点变晚、多删东西）。抽纯函数 + 边界用例。
- 子菜单在 400×600 下的高度：菜单容器已是纵向滚动盒，行数从 1 变 6 需要真机确认
  「清理旧会话」这个父行本身可见（子行可滚动）。
