# TapStack

当前版本：`1.27.0`

最近一次架构重写：`v1.22.0` 无墓碑重写——

1. **删除即删除**：彻底移除墓碑体系（本地回收站、标签级墓碑、URL 去重坟场、空壳清理补丁）。删除**整个会话**前会二次确认（可在设置里关闭；「删除所有会话」始终确认并显示数量），删除后物理清除，不进回收站、不可恢复；**单条标签删除会立即生效，不弹确认**（但若这一删会让整个会话消失，会先确认）；**把最后一条标签拖到别的会话**同样直接生效、不多问一句，而那个被搬空的会话会随之消失（拖拽即剪切，这是核心规则）。
2. **跨设备删除广播**：组删除经 `pendingDeleteIds` 队列 → 云端行标记 `is_deleted`（行保留 = 对端服从删除的载体）→ 30 天后物理清理；标签增删经组级 LWW **整组覆盖**广播（无 tab 级合并）。已知代价：两台设备**同时**编辑同一会话时，胜负由**操作印记**（序号 + 设备编号）决定，**不是**按「谁保存得晚」—— 两边的序号来自互不相关的计数器，先保存的那台也可能赢；赢的一方整组覆盖另一方，败方新增的标签会丢，且没有任何提示。
3. **升级迁移** `tombstones_removed_v1`：首启清除本地全部墓碑组（旧回收站内容，不可恢复）与历史标签级墓碑——修复"计数虚高、恢复不完整"（回收站显示 1000+ 恢复 100+）的根因。

前情：`v1.21.x` 墓碑 7 天生命周期（删除进回收站）+ P0 结构手术（`docs/v2-plan.md` P0 完成态）。**V1.22.0 起已移除墓碑/回收站体系，删除即物理清除。** Yjs 影子双写与相关依赖已于 1.22.11 瘦身时全部删除（决策记录见 `docs/slim-down-plan.md`），同步回到单引擎 + 组级 LWW 快照方案。

---

TapStack 是一个面向重度浏览器用户的工作会话收纳箱。它的核心目标不是“多一个标签管理器”，而是帮你把当前窗口保存成可找回、可恢复的工作现场。

> **关于命名**：早期文档曾把 TapStack 称作「工作会话保险箱」，现已去掉「保险箱」——
> 保险箱的心理契约是「东西丢了能找回来」，而本产品**删除即物理清除、无回收站、不可恢复**
> （这是 1.22.0 起的明确产品决定，见下方「不承诺的能力」）。定位词与实际行为必须一致，
> 否则用户会带着「存进来应该安全」的预期点删除，然后真的丢数据。

## 产品定位

- Save the session
- Find it later
- Restore it when you need it

适合这几类用户：

- 开发者：文档、PR、Issue、控制台、监控、后台同时开很多页
- 研究型用户：论文、论坛、竞品、视频、资料长时间并行打开
- 内容作者：选题、草稿、引用、素材、后台需要反复切换
- 销售 / 招聘 / 投资：CRM、表格、邮件、公司页、Notion 长时间保持上下文

## 当前能力

- 保存当前窗口中的标签页为一个工作会话（整窗 / 单个标签 / 右键菜单 / 快捷键）；**保存 = 剪切：保存后当前窗口的这些标签会被关闭**
- 以后按会话名称、标签标题、URL 找回内容
- 在新窗口中恢复整个会话，尽量不打乱当前窗口
- 新会话默认按内容命名（取出现最多的域名，如 `github.com`），可按需重命名
- 会话重命名、锁定防误删（锁定后不可重命名、不可逐条删除其中的标签、**不可把标签拖到别的会话**、不参与「清理重复标签」；仍可删除整个会话，但会先明确提示「该会话已锁定」，而且这一步**一定**要确认；「删除所有会话」同样会删掉锁定会话，确认框会写明其中有几个锁定会话）、清理重复标签
- 锁定的会话**恢复后仍保留在列表里**，可以反复使用（未锁定的会话恢复后即被消费，从列表移除）
- **「被消费」的那一步有退路**：恢复整个会话、或点开单个标签之后，屏幕上会出现一条带「撤销」按钮的提示，几秒内点一下，那条记录会放回原来的位置（锁定会话从不被消费，也就没有「撤销」）
- 误删保护：删除**整个会话**前会二次确认（可在设置里关闭；「删除所有会话」始终确认并显示数量）；**单条标签删除会立即生效，不弹确认**（但若这一删会让整个会话消失，会先确认）；**把最后一条标签拖到别的会话**同样直接生效、不多问一句，被搬空的会话随之消失；删除即物理清除，无回收站、不可恢复——**删除没有撤销**（上一条那种「从列表移除」才有）
- 支持导入 / 导出 OneTab 文本格式，JSON 备份导出
- 6 套主题风格（legacy / creamy / prism / apple / chrome / claude）+ 暗色模式，单 / 双栏布局
- 登录后同步：数据变更自动上传；**登录成功时立即从云端拉回一次**（新设备登录即看到旧会话）
- 自动同步（后台定时拉取）**默认关闭**；开启后在设置里选 5 / 10 / 30 / 60 分钟四档节奏

## 当前同步模式

当前版本采用**增量自动同步**，并保留手动入口。

**两种后端可选**（右上角 ⋯ 菜单 →「设置…」→ 设置页的「数据同步」段落）：

- **TapStack 云端**（默认）：登录后同步到我们的托管服务（Supabase）。
  存量用户的默认行为**没有任何变化**——`syncBackend` 的默认值就是它，
  升级不会把任何人切到一个没配过的后端。
- **自带存储（WebDAV）**：数据同步到**你自己的云盘**（坚果云、自建 Nextcloud 等），
  不经过我们的服务器。会话内容在离开浏览器前用你的口令加密
  （PBKDF2-SHA256 250k + AES-256-GCM），口令只存在于内存、不落盘。
  详见 `docs/webdav-selfhost-sync-plan.md`。
  两点如实说明：目录清单（manifest）是明文的，云盘服务商能看到「有多少会话、
  何时改过」（不含名称与网址）；选「不加密」则会话名称与网址也可见。
  **新建一个加密库时，口令至少要 12 位**（且不能是常见口令、纯重复、连续字符或键盘上的一排）
  —— 这是这条防线上**唯一**由你决定的变量：云盘服务商手里有 salt（明文在目录清单里）
  与密文文件，能**离线**逐个试你的口令；口令越短，试完越快
  （判据见 `src/sync-backend/webdav/passphrasePolicy.ts`）。
  **已经加密过的库不受影响** —— 原来那个口令哪怕很短也照常能用，不会被要求改掉。
  加密挡的是**离线**（拿到你云盘副本的人看不到会话名与网址），**不挡运行时**
  （已装在你浏览器里的恶意扩展、或有人看着你输入口令，都不受它保护）。

- **自动上传**：保存 / 重命名 / 删除 / 移动 / 锁定等数据变更后，自动防抖推送到云端。
- **自动下载**：默认**关闭**（后台轮询每轮都是出站流量）。开启后按你选的 5/10/30/60 分钟节奏从云端合并拉取到本地；此外，**登录成功时会立即拉一次**，不需要等下一轮。
- **合并安全**：下载采用「快照 → 下载 → 合并 → 校验 → 写入」，合并结果异常时自动回滚，避免同步覆盖丢失本地数据。
- **手动入口**：工具栏同步按钮仍可手动上传（覆盖 / 合并）与下载（覆盖 / 合并），由单一 SyncEngine 统一调度。
- **删除广播**：删除是物理操作（本地不留任何痕迹）。跨设备同步靠云端行上的 `is_deleted` 标记（Supabase migration `supabase/migrations/20260825130248_add_is_deleted_tombstone.sql`，已在生产库执行）——对端合并时该标记优先于旧内容，被删内容不会“复活”。标记行保留约 30 天后物理清除，**清理随同步上传执行；期间不再登录同步的，会推迟到下次同步**（与 `src/legal/privacy.html` 同口径，不承诺无人值守的定时清理）。
- **整组覆盖**：同一会话在两台设备上被**同时**编辑时，整组由**操作印记**（序号 + 设备编号）决胜 —— 序号大的一方赢，序号相同则按设备编号的字典序。**这不是「最后保存的一方赢」**：两台设备的序号来自各自独立的计数器，先保存的那台完全可能赢过后保存的那台。赢的一方**整组覆盖**另一方（会话内标签的增删随整组一起同步，不逐标签合并），败方新增的标签会丢，**且没有任何提示**。错峰使用不受影响。
- **删除 vs 同时编辑**：一台设备删除会话、另一台在离线期间改了它同一个会话时，**删除优先**（云端墓碑一律赢，见 `src/core/opStampMerge.ts`）—— 对方的离线编辑**不会**把删除撤销，那条会话在对方那儿也会消失。代价是：**对方那份离线编辑也一起没了**（不合并、不留副本），删除**没有回收站**。⇒ 真要删干净的会话，删完等一轮同步完成，再确认另一台设备上的那条也没了。
- **冲突不会被报出来**：同步时不会告诉你「刚才两边撞车了」，也不会列出哪一边赢了 —— 界面上看不到冲突提示，只看得到最终结果。
- **单引擎**：所有同步（自动 + 手动 + 设置同步）统一走 `syncEngine.ts`，旧 `syncService` / `smartSyncService` / `tabSyncWorkflow` 已移除。
- TapStack 云端未登录时不触发云端同步；自带存储（WebDAV）用口令解锁、不涉及登录，同步照常发生。
- **保存路径**：管理界面的「保存并关闭」/ 快捷键 Ctrl+Shift+S（macOS 为 ⌘⇧S）/ 右键菜单的「保存其他标签并关闭」都走 SW `TabManager.saveAllTabs()` → `storage.setGroupsImmediate()`；右键菜单的「保存此标签页并关闭」「保存当前标签页并关闭」与快捷键 Alt+S 走 `TabManager.saveCurrentTab()` → `storage.setGroupsImmediate()`。**右键菜单实际只有四项**：在网页或标签标题上右键是「保存此标签页并关闭」，在扩展图标上右键是「保存当前标签页并关闭」「保存其他标签并关闭」与「打开标签管理器」（后者只打开会话管理器，不保存任何东西）；**「保存其他标签并关闭」不含当前那个标签**（它存的是当前窗口里除活动标签以外的其它标签），菜单里没有整窗保存这一项。两条路径都在落盘后立刻调 `syncEngine.scheduleUpload(3000)`（防抖）推送。`autoSyncMiddleware` 仅兜底转发设置类 action（`settings/*`）的上传调度；重命名 / 删除 / 锁定等写操作的上传调度在 SW 侧 `mutationHandlers` 完成；MV3 SW 是独立执行上下文，`syncEngine.upload()` 进入点懒恢复登录态（重复调用是 no-op，与 `backgroundSync` 一致）。**点扩展图标 = 把点到的那个窗口的标签存成会话并关掉它们，随后打开会话管理器**（2026-10-24 产品负责人要求恢复旧交互：单实例里**点图标像在打开什么**确实是误触的来源，但**多 Chrome 实例并存**时旧交互才是对的 —— 动作发生在点的那一边、结果当场可见；2026-10-22 审计 P0-1 的**只打开管理器**被推翻）。窗口取 `chrome.action.onClicked` 传进来的 `tab.windowId`（点的那一个），**不是** `currentWindow`（SW 语境下 = 最后被聚焦的窗口，多窗口/多实例时会指向别处 ⇒ 存错 + 关错）。

## 不承诺的能力

当前版本不把以下能力作为已交付承诺：

- 多端实时并发协同编辑（优先级冲突仍按合并策略解决，非实时）
- **严格意义上的端到端加密（E2E）**。当前实现是：标签页明细在**你的设备上**用 AES-GCM
  加密后上传，云端数据库里存的是密文（传输层另有 HTTPS）。但密钥由**账户 ID 派生**
  （PBKDF2-SHA256，10 万次迭代），而账户 ID 是公开标识、且与密文存在同一张表的同一行——
  任何获得数据库读取权限的一方都能重新派生密钥并解出明文。
  准确的说法是「**传输加密 + 服务端静态加密**」，**不是端到端加密**。
  想要真正的 E2E，需要改成由你的口令派生密钥（Argon2id）+ 服务端盲存，
  代价是新增一套「恢复码 / 换设备递送密钥」的机制——这是一次独立的、大改。
  在那之前，请不要把云端数据当作「只有你能看见」。

## 使用方式

### 保存会话

- 点扩展图标即可把当前窗口的标签页存成一个会话**并关掉它们**；也可在主界面点击“保存并关闭”，或按 Ctrl+Shift+S（macOS 为 ⌘⇧S）
- 当前窗口中的标签页会被保存成一个新会话，**这些标签随即被关闭**（保存 = 剪切）
- 可配置是否一并保存固定标签页
- 浏览器内部页面（设置页、扩展页等）一律不保存；本地文件（`file://`）的地址会照常存下来（否则 PDF、论文这类标签会被悄悄丢掉），但它在别的设备上不一定打得开

### 找回会话

- 在搜索框中输入会话名、标签标题或 URL
- 搜索结果会优先展示匹配到的会话，再展开具体标签命中
- 可按域名、会话名称、保存时间筛选，**不输入关键词也能用**（点列表上方的「显示筛选」即可）
- 「固定标签页」筛选仅在设置里开启「保存固定标签页」后出现（关闭时存进会话的标签本就没有固定标记，这个筛选无从谈起）

### 恢复会话

- 点击会话卡片上的“恢复整个会话”
- 会在新窗口中恢复该会话
- 未锁定会话恢复后会从列表中移除；锁定会话会保留
- 点开单个标签继续浏览时，该条会自动从会话移除（锁定会话除外）；本设备打不开的地址（本地文件、内部页面）会提示并保留记录
- **这两种「移除」都可以撤销**：移除后屏幕上会出现一条带「撤销」按钮的提示，几秒内点一下，那条记录会放回**原来的位置**（锁定会话从不被移除，也就没有「撤销」）；撤销同时会撤回那次「让别的设备也删掉它」的意图，所以不会出现「本机撤销了、别的设备上却没了」

### 会话命名

- 新保存的会话默认按**内容**命名：取这批标签里出现最多的域名（如 `github.com`）
  —— 一眼能看出「这是哪个工作现场」，而不是一列时间戳
- 本机地址与内网 IP（`localhost:3000`、`192.168.1.5`、`[::1]:8080` 等）按**主机名**命名 —— 对自建服务来说，主机名就是它的名字
- 连主机名都没有时（内部页面等）取**页面标题**；标题也没有才回落到 `标签组 + 保存时间`
- 你可以在保存后手动重命名，让会话更容易再次找回
- 更早版本保存的会话仍是时间戳命名，重命名一次即可，不会被自动改动

### 导入 / 导出

- 支持 JSON 备份导出
- 支持 OneTab 文本导入和导出
- **网址与标题原样往返**：网址里带竖线（`?q=foo|bar` 这类代码搜索链接）、
  标题里带竖线或换行，都不会被截断、也不会被拆成两条
- **导入的会话怎么命名，分两种**：
  - 导回**本扩展导出的 JSON 备份** ⇒ 会话名**原样保留**（备份里叫什么就叫什么），
    **锁定状态也保留**；
  - 导入 **OneTab 文本** ⇒ 那个格式**本身不带会话名**（所以名字一定会丢），
    会话按内容命名：取这批标签里出现最多的域名（如 `github.com`），
    取不到域名时回落到「导入的会话 1、2、3…」。
    ⚠️ **OneTab 导入的会话一律不带锁定状态**（那个格式里没有这个信息）——
    想让它防误删，导入后记得重新锁定。

## 隐私与数据

- 本地数据默认保存在浏览器的 **IndexedDB**（扩展的本地数据库）中，仅存于你的设备；扩展同时用 `chrome.storage` 保存登录状态与少量设置标记。会话数据不受 `chrome.storage` 的容量配额限制（v1.25.1 起不再申请 `unlimitedStorage` 权限）
- 开启同步后，云端数据仅用于跨设备找回和主动触发的同步。**注意「自带存储」不需要登录**：用它的用户即使没有 TapStack 账号，数据也会离开设备，只是离开的方向是他自己的云盘。同步会上传会话明细与界面偏好设置（主题、布局等）；与设备本身有关的三项（用哪个后端、是否开启自动同步、同步间隔）始终以本机为准，不上传；登录状态与云盘凭据只留在本机。
- 同步采用增量防抖：保存 / 重命名 / 删除 / 锁定后自动上传云端；后台 alarm 按你选的间隔（5/10/30/60 分钟，默认 10 分钟）拉取云端变更到本地（TapStack 云端未登录不触发；自带存储用口令解锁、不涉及登录）。自动同步默认关闭：关掉的是**后台轮询 alarm**；每次本地保存 / 重命名 / 删除仍会安排一次**延迟上传**（扩展进程存活时约 1.5–3 秒后触发；浏览器把扩展挂起时改由后台 alarm 兜底，而 Chrome 规定 alarm 的最小延迟是 30 秒），与自动同步开关无关。
- 你可以随时用手动入口（同步按钮）切换“合并 / 覆盖”模式或强制重新同步
