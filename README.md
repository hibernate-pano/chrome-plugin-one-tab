# TapStack

当前版本：`1.24.1`

最近一次架构重写：`v1.22.0` 无墓碑重写——

1. **删除即删除**：彻底移除墓碑体系（本地回收站、标签级墓碑、URL 去重坟场、空壳清理补丁）。删除前确认保留（删除全部强制确认），删除后物理清除，不进回收站、不可恢复。
2. **跨设备删除广播（自带存储 / WebDAV）**：组删除经 `pendingDeleteIds` 队列 → 上传时把该会话的远端分片覆写成墓碑（`isDeleted: true` + 新 OpStamp，并登记进 `manifest.json`）→ 对端合并时服从删除、不会“复活”；墓碑约 30 天后由同步上传顺带物理清理（期间不再同步则推迟到下次同步）。标签增删经组级 LWW **整组覆盖**广播（无 tab 级合并）。已知代价：两台设备同时编辑同一会话，后保存方整组赢。
3. **升级迁移** `tombstones_removed_v1`：首启清除本地全部墓碑组（旧回收站内容，不可恢复）与历史标签级墓碑——修复"计数虚高、恢复不完整"（回收站显示 1000+ 恢复 100+）的根因。

前情：`v1.21.x` 墓碑 7 天生命周期（删除进回收站）+ P0 结构手术（`docs/archive/v2-plan.md` P0 完成态）。**V1.22.0 起已移除墓碑/回收站体系，删除即物理清除。** Yjs 影子双写与相关依赖已于 1.22.11 瘦身时全部删除（决策记录见 `docs/archive/slim-down-plan.md`），同步回到单引擎 + 组级 LWW 快照方案。

---

TapStack 是一个面向重度浏览器用户的工作会话收纳箱。它的核心目标不是“多一个标签管理器”，而是帮你把当前窗口保存成可找回、可恢复的工作现场。

> **关于命名**：早期文档曾把 TapStack 称作「工作会话保险箱」，现已去掉「保险箱」——
> 保险箱的心理契约是「东西丢了能找回来」，而本产品**删除即物理清除、无回收站、不可恢复**
> （这是 1.22.0 起的明确产品决定，见下方「不承诺的能力」）。定位词与实际行为必须一致，
> 否则用户会带着「存进来应该安全」的预期点删除，然后真的丢数据。

![TapStack](icons/icon128.png)

## 产品定位

- Save the session
- Find it later
- Restore it when you need it

适合这几类用户：

- 开发者：文档、PR、Issue、控制台、监控、后台同时开很多页
- 研究型用户：论文、论坛、竞品、视频、资料长时间并行打开
- 内容作者：选题、草稿、引用、素材、后台需要反复切换
- 销售 / 招聘 / 投资：CRM、表格、邮件、公司页、Notion 长时间保持上下文

## 当前能力

- 保存当前窗口中的标签页为一个工作会话（整窗 / 单个标签 / 右键菜单 / 快捷键）
- 以后按会话名称、标签标题、URL 找回内容
- 在新窗口中恢复整个会话，尽量不打乱当前窗口
- 新会话默认按保存时间生成时间戳名称，可按需重命名
- 会话重命名、锁定防误删、清理重复标签
- 误删保护：删除前二次确认（删除全部强制确认），删除即物理清除
- 支持导入 / 导出 OneTab 文本格式，JSON 备份导出
- 6 套主题风格（legacy / creamy / prism / apple / chrome / claude）+ 暗色模式，单 / 双栏布局
- 跨设备同步（自带存储 / WebDAV）：配置自己的云盘后，数据变更自动加密上传；下载默认手动，可在设置里开启定时自动同步

## ⚠️ 1.24.1 及更早的账户用户：先导出，再升级

TapStack 在 2026-10-16 之前提供账户登录，登录后的会话同步到我们托管的 Supabase 后端。**当前仓库的新版本已删除账户与 Supabase 客户端代码，WebDAV 是唯一同步方式，新版本读不到托管后端里的数据。** 托管后端里的数据本身仍然存在；只要后端未关停，旧版本（1.24.1 及更早）仍能登录并导出。

**先判断你属于哪种情况**

| 情况 | 你能做什么 |
|---|---|
| 扩展仍是 1.24.1 或更早（**在 WebDAV-only 版本上架前，商店里的 TapStack 仍是账户版**；2026-10-16 实测线上为 1.24.1） | 现在就能直接导出，按下文「第 1 步」做 |
| 已经升级到没有登录入口的新版本，但升级前复制过旧版目录 | 用「加载已解压的扩展程序」加载那份副本，再按「第 1 步」导出 |
| 已经升级且没有旧版副本 | 目前没有自助办法，联系我们（见「第 2 步」最后一则） |

**第 1 步：在旧版本里导出（顺序不要颠倒）**

1. 打开 TapStack，用你原来的邮箱与密码登录。
2. 点同步按钮，选择「下载」（推荐「合并」，不会覆盖本地会话），把云端会话拉到本地。
3. 核对列表：确认你需要的会话（尤其只存在于云端、本机没有的那些）都出现了。
4. 打开右上角菜单 → **导出数据 → JSON 格式**，把全部会话保存成一个 `.json` 文件。
5. 把该文件放到浏览器之外（桌面 / 网盘 / 移动硬盘），并用文本编辑器打开，确认能看到会话名与网址。
6. 确认备份可用之后，再升级或卸载。升级不会删除本机已有的会话，但会移除账户登录入口。

**第 2 步：怎么「装回旧版本」——可行的和不可行的都写清楚**

- **Chrome 应用商店不提供旧版本下载或回退**：商店页面没有 previous version，开发者也做不到让用户装回已下架的版本。第三方「CRX 下载站」来源不可信，不要用。
- **可行（最省事）**：在新版本上架之前，直接从商店安装 / 更新 TapStack——截至 2026-10-16，商店上架的 1.24.1 仍是账户版；装上后就能登录、导出。这是一条**有期限**的路：移除账户体系的新版本一旦上架，商店给新用户的只有新版，Chrome 也会把老用户自动升级过去。
- **可行（升级后仍要取回）**：在升级前，把已安装的旧版扩展目录复制出来留档，之后用「加载已解压的扩展程序」加载它。
  - macOS：`~/Library/Application Support/Google/Chrome/<配置文件>/Extensions/bbbpnccbclnnphchghpfmcjjfhigepbk/1.24.1/`
  - Windows：`%LOCALAPPDATA%\Google\Chrome\User Data\<配置文件>\Extensions\bbbpnccbclnnphchghpfmcjjfhigepbk\1.24.1\`
  - Linux：`~/.config/google-chrome/<配置文件>/Extensions/bbbpnccbclnnphchghpfmcjjfhigepbk/1.24.1/`

  （`<配置文件>` 通常是 `Default` 或 `Profile 1` 等；路径里的扩展 ID `bbbpnccbclnnphchghpfmcjjfhigepbk` 就是 TapStack 的商店 ID。）然后打开 `chrome://extensions` → 打开右上角「开发者模式」→「加载已解压的扩展程序」→ 选中复制出来的 `1.24.1` 文件夹。
  **注意**：这样加载的副本扩展 ID 与商店版不同，它看不到你本机原来的会话（`chrome.storage` 按扩展 ID 隔离）；但用原账户登录后，云端数据会照常下载，导出不受影响。这份副本不会自动更新，请只把它当成一次性的导出工具，用完删掉。
- **不可行：从仓库源码构建 v1.24.1**。旧版构建需要 Supabase 项目地址与 anon key（当时只存在于构建环境的 `.env` 里，没有进仓库），所以照仓库 tag 构建出来的旧版登录不了。除非你清楚怎么拿到这些配置，否则不要走这条路。
- **已经升级、也没有保留副本**：目前**没有自助办法**。请发邮件到 privacy@tapstack.app（或到 GitHub Issues 留言），注明账户邮箱，我们会确认托管后端状态并尽力协助导出——**前提是后端尚未关停**。请如实理解：这不是能单方面保证的恢复通道。
- 如果你有多个 Chrome 配置文件（Profile），旧版可能还留在其中一个尚未更新的配置文件里：打开 `chrome://extensions` 看版本号，先别再升级它。

**第 3 步：跳过导出会丢什么**

- 只存在于托管后端、没有落到本机的会话：托管后端关停后**永久无法恢复**（本产品没有回收站、没有撤销）。
- 本机已有的会话不会因升级而消失；但本机不是备份——卸载扩展、清理浏览器数据都会带走它。
- **跳过导出的代价是不可逆的**：这不是「以后再说」的选项，后端关停后连开发者也无法帮你取回。

**期限**

托管后端目前仍然在线，但关停日期尚未确定；一旦确定，我们会提前在隐私政策页、README 与商店更新说明中公告。实际可用的截止日 = 「移除账户体系的新版本上架、你的扩展被自动升级」与「托管后端关停」两者中较早的那个，而 Chrome 的自动升级可能在你不注意时发生。一旦自动升级完成，扩展内的导出入口就不存在了；此后唯一可能的取回途径是一份旧版本构建副本（你在升级前从 Chrome 配置目录复制的那份；自行从 v1.24.1 tag 构建因旧后端地址与密钥未进仓库而行不通），而已经自动升级且从未保留副本的用户，目前没有可自助执行的路径，这个情形不可恢复，请联系 privacy@tapstack.app（能否协助取决于后端是否尚未关停）。跳过导出的会话将永久无法恢复——请现在导出，不要等公告。

## 当前同步模式

当前版本采用**增量自动上传 + 手动 / 定时下载**。跨设备同步的**唯一后端是自带存储（WebDAV）**——扩展不再提供任何账户体系，数据只存在你的浏览器与**你自己的云盘**里。设计说明见 `docs/webdav-selfhost-sync-plan.md`。

**配置方式**（设置页 →「自带存储（WebDAV）」）：

- 填入 WebDAV 地址、账号、应用密码与子目录；坚果云地址 `https://dav.jianguoyun.com/dav/` 已预填，自建 Nextcloud 等填自己的 WebDAV 根目录（必须以 `/` 结尾）。
- 「应用密码」指云盘服务商的第三方应用专用密码，不是你的账号登录密码。
- 首次连接需要在点击「测试连接」或「检查并推送到云端」时授予该地址的浏览器访问权限；安装扩展时**不索要任何网站访问权**（`manifest.json` 的必选主机权限为空，网络权限为运行时按需申请）。
- 保存后会引导你「检查并推送到云端」：本地与云端都有数据时，由你选择合并 / 以本机为准 / 以云端为准，绝不静默覆盖任何一方。

**加密**：

- 选「加密」（默认）时，会话内容在**离开浏览器之前**用你的口令加密（PBKDF2-SHA256 250k + AES-256-GCM），云盘上只有密文。密钥由**你的口令**派生，口令与派生密钥只存在于本次浏览器会话的内存中、不落盘，我们与云盘服务商都拿不到——属于真正的端到端加密。
- 两点如实说明：目录清单（`manifest.json`）以明文存放，云盘服务商能看到「有多少个会话、各自何时被修改」（不含名称与网址）；选「不加密」则会话名称与网址也可见。
- 口令没有找回入口，忘记后云盘上的数据将无法解密。

**同步行为**：

- **自动上传**：保存 / 重命名 / 删除 / 移动 / 锁定等数据变更后，自动防抖推送到你的云盘（需已配置并解锁）。删除走更短的优先窗口。
- **下载**：默认不自动拉取；点工具栏同步按钮可手动下载（合并 / 覆盖）。想自动拉取，在设置里打开自动同步并选择 5 / 10 / 30 / 60 分钟间隔（默认 10 分钟），后台按间隔检查云盘变更并合并到本地。
- **合并安全**：下载采用「快照 → 下载 → 合并 → 校验 → 写入」，合并结果异常时自动回滚，避免同步覆盖丢失本地数据。
- **删除广播**：删除是本地物理操作（不留痕迹）。跨设备同步靠远端墓碑分片传播（见上）——对端合并时服从删除，被删内容不会“复活”。墓碑与该分片在约 30 天后由同步任务物理清除，**清理随同步上传执行；期间不再同步的，会推迟到下次同步**（与 `src/legal/privacy.html` 同口径，不承诺无人值守的定时清理）。
- **整组覆盖**：同一会话在两台设备上被同时编辑时，以**最后保存的一方**为准（会话内标签的增删随整组一起同步，不逐标签合并）。错峰使用不受影响。
- **单引擎**：所有同步（自动 + 手动 + 设置同步）统一走 `syncEngine.ts`，旧 `syncService` / `smartSyncService` / `tabSyncWorkflow` 已移除。
- **未配置 / 未解锁时 fail-closed**：不会回落到任何其他后端，而是中止本轮同步并给出可行动的提示。
- **保存路径**：popup 按钮 / 快捷键 / 右键菜单都走 SW `TabManager.saveAllTabs()` → `storage.setGroups()` 后立刻调 `syncEngine.scheduleUpload()`（防抖）推送。`autoSyncMiddleware` 仅兜底转发设置类 action（`settings/*`）的上传调度；重命名 / 删除 / 锁定等写操作的上传调度在 SW 侧 `mutationHandlers` 完成。

## 不承诺的能力

当前版本不把以下能力作为已交付承诺：

- 多端实时并发协同编辑（优先级冲突仍按合并策略解决，非实时）
- **口令找回**：WebDAV 加密口令没有找回入口。忘记后云盘上的数据无法解密，我们无法补救。
- **托管服务**：当前版本没有 TapStack 账户，也没有我们的云端服务器。代价是跨设备必须自备一个
  WebDAV 云盘，且云盘上的目录清单（manifest）是明文的——服务商能看到「有多少会话、
  何时改过」（不含名称与网址）；选「不加密」则名称与网址也可见。
  注意：2026-10-16 之前使用过账户体系的用户，其历史数据仍托管在我们当时的后端上，适用
  上方「1.24.1 及更早的账户用户：先导出，再升级」一节，不适用本条的「没有云端服务器」描述。

## 安装

### 从 Chrome 商店安装

- 访问 [Chrome Web Store](https://chrome.google.com/webstore) 并搜索 `TapStack`

### 开发模式安装

```bash
git clone https://github.com/hibernate-pano/chrome-plugin-one-tab.git
cd chrome-plugin-one-tab
pnpm install
pnpm build
```

然后在 `chrome://extensions/` 中开启开发者模式并加载 `dist` 目录。

## 使用方式

### 保存会话

- 点击扩展图标，或在主界面点击“保存会话”
- 当前窗口中的标签页会被保存成一个新会话
- 可配置是否一并保存固定标签页

### 找回会话

- 在搜索框中输入会话名、标签标题或 URL
- 搜索结果会优先展示匹配到的会话，再展开具体标签命中
- 可按域名、固定标签、保存时间继续筛选

### 恢复会话

- 点击会话卡片上的“恢复整个会话”
- 会在新窗口中恢复该会话
- 未锁定会话恢复后会从列表中移除；锁定会话会保留
- 点开单个标签继续浏览时，该条会自动从会话移除（锁定会话除外）；本设备打不开的地址（本地文件、内部页面）会提示并保留记录

### 会话命名

- 新保存的会话默认命名为 `标签组 + 保存时间`
- 你可以在保存后手动重命名，让会话更容易再次找回

### 导入 / 导出

- 支持 JSON 备份导出
- 支持 OneTab 文本导入和导出

## 隐私与数据

- 本地数据默认保存在浏览器扩展存储中；不配置云盘时，数据不离开本机
- 配置后，数据只会发往**你自己填写的 WebDAV 云盘地址**；当前版本没有服务器，也不设账户。2026-10-16 之前注册过账户的用户，其历史数据仍托管在当时使用的后端上——导出与删除办法见上方「1.24.1 及更早的账户用户：先导出，再升级」
- 同步采用增量防抖：保存 / 重命名 / 删除 / 锁定后自动加密上传；下载默认手动，开启自动同步后按你选的间隔（5 / 10 / 30 / 60 分钟，默认 10 分钟）拉取
- 应用密码与加密口令只存在于本次浏览器会话的内存中，关闭浏览器后需重新输入，不写磁盘
- 云盘上的目录清单（manifest）是明文的：服务商能看到会话数量与修改时间，不含名称与网址；选「不加密」则名称与网址也可见
- 删除即物理清除（本地无回收站）；云盘上的墓碑分片约 30 天后由同步任务清理，期间不再同步也不会触发定时清理
- 你可以随时用手动入口（同步按钮）切换“合并 / 覆盖”模式或强制重新同步
