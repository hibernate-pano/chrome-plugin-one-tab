## 二、执行过程

### 修复 1：全量迁移进 SW 单写者队列

- `service-worker.ts`：`migrateToV2()` 从裸调用改为
  `await enqueue('storageMigrations', async () => { … })`，与下一行
  `ensureOpStampMigrated`（改为 `true` = 队列内就地串行）合并成**同一个 job**。
  不拆三次入队：中途插一个 mutation 会让「迁移半成品」暴露给用户可见列表。
- 新增消息分支 `RUN_MIGRATIONS` → `enqueue('storageMigrations', runStorageMigrations)`。
- `TabList.tsx`：不再 `import { runMigrations }` 直接调用，改发 `RUN_MIGRATIONS`
  消息，并**显式检查回包**（`sendMessage` 对 `{success:false}` 是 resolve 不是 reject，
  不检查就是失败静默通过）。
- `migrationUtils.runMigrations()`：去掉 `catch { logError }` 的吞错。原注释说
  「不抛出错误，避免影响应用启动」——在新结构下这条理由已不成立，且吞错会让
  `RUN_MIGRATIONS` 永远回 `success:true`，迁移失败与成功同形。调用方各自
  try/catch 并照常 `loadGroups()`，应用启动与迁移失败已解耦。

## 三、遇到的问题（报错、阻塞、意外行为）

### 问题 1：我把守卫写在了被变异的函数内部（自我指涉，与 glob P0-1 同类）

第一版把 `listingBody()` 的校验**写在函数体内**。变异验证时把整个函数替换为
坏抽取，守卫**跟着一起被替换掉** → 14/14 全绿。
**这是我自己犯的、和我刚修的 P0-1 完全相同的错误**：守卫住在它要防的那个对象里。
修法：改成独立的 `expectedListingBody()`（另一种定位方式）+ 独立测试用例，
两套实现只在都正确时才相等。

### 问题 2：模板字符串里写了反引号，提前终止字符串

给 `DASHBOARD_FIXTURE` 加 GRANT 注释时用了 `` `permission denied` ``，
而该注释**在模板字符串内部** → 反引号终止模板串 →
`SyntaxError: Expression expected`。去掉反引号后恢复。
这正是 `_shared.md` 陷阱里「注释里出现定界符会腰斩字符串」的同类坑。

### 问题 3：断言把「SET ROLE 的回显」当成数据

`psql -tA -c "SET ROLE anon; SELECT count(*)…"` 输出是 `"SET\n0"`。
我直接与 `'0'` 比较 → 报「anon 能读到 tab_groups SET 0 行」。
**实际 RLS 已生效（真实值 0），错误信息却长得像真缺陷。**
新增 `lastLine()` 取最后一个非空行。

### 问题 4：断言「匿名 UPDATE 必须抛 42501」是错的

PostgreSQL 语义：`USING` 不匹配的行被**过滤**，UPDATE 影响 0 行、**不报错**；
42501 只在 `WITH CHECK` 失败时抛。「不抛错」本就是安全表现。
我差点把安全行为当成漏洞。改为验证**数据有没有被篡改**（UPDATE 后 name 必须仍是 other）。

### 问题 5：新测试插错了 describe 作用域

`SRC` 是 `describe('migrate.mjs 的 verify…')` 内的局部常量，我把测试插到了
隔壁 `describe('迁移幂等：SQL 结构护栏')` 里 → `ReferenceError: SRC is not defined`。
用括号/标记精确定位后移动。

### 问题 6：变异验证无效（基线就是红的）

跑变异 F/G 时发现**基线 13 tests / 12 pass / 1 fail** —— 我的新测试本身失败。
变异 F、G 也都是同一个 fail，**变异对照完全无效**（改坏不改坏都红）。
先修基线到 13/13，再重做变异，才得到有效对照。

### 问题 7：收紧后又发现守卫太弱（变异 G 假绿）

第一版守卫写 `fn.includes("'tab_groups'")`，而 `fn` 同时覆盖**常量定义**与
**函数体**；函数体里恰好有 `disabled.some(t => ['tab_groups',…])`。
于是把常量里的 tab_groups 删掉、**变异仍 13/13 全绿**。
变异验证当场抓出这个盲区。改为只认 `const RLS_REQUIRED_TABLES = [ … ];`
这一段字面量后，变异 G 变红。

### 问题 8：既有守卫绑死在精确字符串上，我加检查项后假红

`migrationExecutionSafety` 用
`src.slice(src.lastIndexOf('if (!okRls || !okPurge)'))` 定位。
我给 verify 加了第三个检查项 `okRlsTables` → `lastIndexOf` 返回 -1
→ `slice(-1)` 取到最后一个字符 → 断言失配，全量 1007/1 fail。
改为按**意图**断言（有 `if (!ok)` 保护 + 保护里 return false + VERIFY OK 在其后），
不再绑变量名。
