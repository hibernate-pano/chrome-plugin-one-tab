## 遇到的问题

### 问题 1（唯一的真实阻塞）：OAuth refresh token 失效

**现象**：第一次 `status` 直接抛错

```
Error: 换 access token 失败: {
  "error": "invalid_grant",
  "error_description": "Token has been expired or revoked."
}
```

**排查**：
1. 先排除网络/代理 —— `curl -x http://127.0.0.1:7897` 打 Google token 端点与 CWS API，分别返回 404（端点正常，该 URL 本就不存在）和 401（需要鉴权，说明网络通）。结论：不是代理问题，是 token 真失效。
2. 找到 `chrome-plugin-video-manager/scripts/store-auth.mjs`（一次性 OAuth 授权脚本，把 refresh token 追加写到 `/Users/panbo/Code/.env`，仓库外），准备复用。

**踩坑 A —— 第一次授权失败：`invalid_client`**：
导出的是 `CWS_CLIENT_ID` / `CWS_CLIENT_SECRET`，但 `store-auth.mjs` 读的是 **`CLIENT_SECRET`** 环境变量，读不到就回退读 `ENV_PATH` 里那份 ⇒ 静默用错了凭证。
用「`Code/.env` 的 CLIENT_SECRET + mcp.json 的 CLIENT_ID」组合也是 `invalid_client`。

**踩坑 B —— 排查中的关键分叉**：
我用 dummy refresh token 分别打两份凭证，结果**错误码不同**，这个差异就是破案点：
- `mcp.json` 那份 → `invalid_grant: Bad Request`（**client 是好的**，是那个 refresh token 被吊销）
- `Code/.env` 那份 → `invalid_client: The provided client secret is invalid.`（**这份 secret 本身已失效**）

也就是说仓库外 `.env` 里存的是一份**过期的 OAuth 客户端**，mcp.json 里那份才是当前配对正确的。之前两次失败是我自己把变量名和凭证源搞混，不是同一件事。

**解决**：用 `mcp.json` 的 `CWS_CLIENT_ID` + `CWS_CLIENT_SECRET` 正确映射成 `CLIENT_ID` / `CLIENT_SECRET` 再跑授权脚本。浏览器授权页一次通过，`REFRESH_TOKEN` 写入 `/Users/panbo/Code/.env`（沿用既有做法，不进 git）。之后所有 API 调用正常。

### 问题 2（工具限制，非阻塞）：v2 `fetchStatus` 不可用

台账顶部写着「用 v2 API fetchStatus 核实」，但实测 `chromewebstore.googleapis.com/v2/...:fetchStatus` 返回**空响应体** —— 与 `cws-publish.mjs` 文件头记录的一致：**本凭证 v2 端点一律 404，别再试**（这与 video-manager 仓库的结论不同，那边 v2 可用）。

这是不可逆的生产写操作，本想在 upload 前用 `request_user_input` 让 Jasper 最后确认一次，但该工具在 Default 模式不可用。
判断依据：用户指令明确（"请将此插件发布到 Chrome 商店"）、线上版本低于待发版本、构建包逐项核验通过、1314 测试全绿、validate exit 0 —— 继续等待反而违背「没有做完的任务必须自动继续」的纪律，于是直接执行，并在最终回复里如实说明这一点。

## 沉淀的教训

1. **`invalid_client` 与 `invalid_grant` 是两个完全不同的故障，必须分开读**。前者是 OAuth 客户端（id/secret 配对）坏了，后者只是 refresh token 过期。用 dummy token 各打一次就能立刻分叉定位 —— 这是本次破案的关键动作，以后遇到 OAuth 失败先做这个区分。
2. **同名环境变量跨脚本不通用**。`store-auth.mjs` 读 `CLIENT_SECRET`，`cws-publish.mjs` 读 `CWS_CLIENT_SECRET`，前者读不到会**静默回退**到 `.env` 里的另一份凭证，于是报出一个指向错误方向的超时/认证错误。以后复用跨仓库脚本时，先确认它读的确切变量名。
3. **「上传成功」不能推出「发布成功」**。空草稿 publish 返回 200 但是 no-op，脚本本身已经为这一条加了自校验；我额外在 publish 前查一次 `crxVersion`，把间接推断换成直接证据。
4. **台账会漂移，但公开商店页不会**。抓一次商店页 HTML 就能拿到线上真版本，成本极低，值得每次发版前做。
5. **凭证写在仓库外是对的**，但仓库外也会积累过期副本（`Code/.env` 里那份 OAuth 客户端已经失效）。存了两份凭证时，要定期用一次真实请求验证哪份还活着。
